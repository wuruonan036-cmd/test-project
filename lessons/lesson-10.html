第 10 课 · Week 3

RAG / Knowledge Base：让模型使用可靠外部知识

理解知识入库、向量检索、重排、引用和 RAG 与数据库、Memory 的边界。

RAGEmbedding检索

课程目标

理解知识入库、向量检索、重排、引用和 RAG 与数据库、Memory 的边界。

1. 本课问题域

大模型本身有很多通用知识，但它有几个天然限制：

text
1. 不知道学习者的私有资料
2. 不知道实时变化的信息
3. 可能记错或编造
4. 不能天然引用学习者的业务文档
5. 无法保证回答依据来自指定来源

RAG 的目的在于让模型回答前获得可靠外部资料，而并非单纯增强聊天表现。

一句话定义：

RAG（Retrieval-Augmented Generation）= 先检索相关知识，再让模型基于检索结果生成回答。

LlamaIndex 官方资料把 RAG 解释为：LLM 没有训练在学习者的私有数据上，RAG 通过把学习者的数据加入模型可访问的信息中来解决这个问题。OpenAI 的 Retrieval 文档也把 vector stores 作为数据索引，用于语义搜索和检索。

2. RAG 在知识树里的位置

text
用户输入
→ 后端接收
→ Harness 判断是否需要外部知识
→ RAG 检索知识库
→ 把检索结果放进 Context
→ 调用模型生成回答
→ 输出答案
→ 写入日志 / 评测

RAG 不等于数据库，不等于 Memory，也不等于搜索引擎。

它更像是：

text
“给模型临时发一份参考资料”

3. RAG 的基本链路

完整 RAG 分两段。

A. 知识入库阶段

text
原始资料
→ 清洗
→ 切块 Chunk
→ 生成 Embedding
→ 存入 Vector Database / Vector Store
→ 建立索引

B. 用户查询阶段

text
用户问题
→ 问题向量化
→ 在向量库中检索相似知识片段
→ 可选：Reranking 重排
→ 选出最相关片段
→ 放进模型上下文
→ 模型基于这些片段回答

4. 基础解释：Embedding 是什么

可以这样理解：

Embedding 是把一段文字变成一组数字，让计算机可以判断“语义相似度”。

例如：

text
“孕晚期胎动减少怎么办”

和：

text
“怀孕后期宝宝动得少了需要注意什么”

字面不一样，但语义接近。

Embedding 会把它们转成向量，系统可以计算它们的距离。OpenAI 官方文档也说明，embedding 是浮点数列表，两个向量之间的距离可以表示相关性，距离小通常表示相关性高。

5. 基础解释：Vector Database 是什么

普通数据库适合查：

text
用户 ID = 123
订单状态 = paid
创建时间 > 2026-01-01

向量数据库适合查：

text
意思和“胎动减少”最接近的知识片段

所以：

查询类型更适合
精确查用户资料普通数据库
模糊查语义相近资料向量数据库
查长期用户偏好Memory / 普通数据库 / 向量检索结合
查实时业务状态普通数据库 / Tool
查权威知识片段RAG / Vector Store

6. RAG 和普通搜索有什么区别

普通搜索更偏关键词：

text
关键词匹配：胎动 + 减少

RAG 更偏语义：

text
语义匹配：用户在问胎动变少是否危险

但不要神化 RAG。RAG 也会失败。

常见失败包括：

text
1. 知识库资料本身不准
2. 文档切块太差
3. 检索出来的片段不相关
4. 模型没有严格基于资料回答
5. 没有引用来源
6. 没有处理资料之间的冲突

7. RAG、Database、Memory 的边界

这是重点。

模块存什么什么时候用例子
Database结构化业务数据精确查询用户预产期、账号、记录、订单
RAG外部知识资料需要事实依据时孕期检查知识、产品文档、医学说明
Memory用户长期状态需要理解用户个人连续性时用户偏好、长期担忧、曾经发生过的重要事件

一句话：

text
Database = 系统事实
RAG = 外部知识
Memory = 个人状态

8. 在学习者的项目里，RAG 可能负责什么

这里只作为案例，不反推知识结构。

孕产陪伴产品中，RAG 可能负责：

text
1. 孕期阶段知识
2. 检查指标解释
3. 红旗信号说明
4. 产后恢复基础知识
5. 新生儿早期照护知识
6. 产品内部规则文档
7. 医疗安全边界说明

但注意：

高风险场景不能只靠 RAG。

RAG 只是提供知识，不负责最终安全裁决。

最终安全裁决应由：

text
Harness
+ Risk Detection
+ Guardrails
+ 固定安全策略
+ 必要时人工/医生/线下就医建议

共同完成。

9. 学习者需要看懂的最小代码结构

无需掌握编写细节，但要能看懂大概位置。

python
# 伪代码：RAG 查询链路
def answer_with_rag(user_question):
    query_vector = embed(user_question)
    docs = vector_store.search(
        vector=query_vector,
        top_k=5
    )
    context = build_context(
        question=user_question,
        retrieved_docs=docs
    )
    answer = call_llm(context)
    return answer

只需看懂：

text
embed() = 把问题变成向量
vector_store.search() = 检索相似知识
build_context() = 把资料拼进上下文
call_llm() = 调模型回答

10. 实战判断：什么时候不该用 RAG

不要什么都 RAG。

场景是否需要 RAG判断
用户问“你能陪我聊会儿吗”通常不需要这是陪伴对话
用户问“我上次说的那个检查是什么”不一定可能查 Memory / 历史记录
用户问“妊娠糖耐异常是什么意思”需要需要权威知识
用户问“我的预产期是哪天”不需要 RAG查数据库
用户上传检查单要求解释可能需要OCR + 数据库 + RAG + 安全边界
用户问“现在东京天气”不需要 RAG用 Tool / 外部 API
