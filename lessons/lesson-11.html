第 11 课 · Week 3

Memory 系统：面向未来任务的状态管理

区分聊天记录与可复用记忆，理解记忆读写、保留、删除和风险控制。

Memory用户画像长期状态

课程目标

区分聊天记录与可复用记忆，理解记忆读写、保留、删除和风险控制。

1. 本课问题域

没有 Memory 的 AI 应用，每次交互都缺少长期状态基础。

它只能依赖：

text
当前输入
+ 当前会话上下文
+ 临时传入的信息

但真实产品里，用户希望系统能持续理解：

text
我是谁
我现在处于什么阶段
我之前发生过什么
我偏好什么
我讨厌什么
我有哪些未完成事项

Memory 要解决的，就是这种长期连续性问题。

一句话定义：

Memory = 从过去信息中提取未来任务有用的状态。

注意：Memory 的目标并非保存全部聊天记录，而应是沉淀未来任务可复用的状态。

2. Memory 在知识树里的位置

text
用户输入
→ Harness 判断是否需要个人历史
→ Memory 检索相关状态
→ 注入 Context
→ 模型生成
→ Harness 判断是否写入新记忆
→ 用户可查看 / 编辑 / 删除

Memory 同时发生在两处：

text
读记忆：这次回复前，拿出相关记忆
写记忆：这次回复后，判断是否新增/更新记忆

3. Memory 和聊天记录的区别

类型是什么是否等于 Memory
聊天记录所有原始对话并非
摘要对话压缩版可能是 Memory 输入
用户资料结构化个人信息是一种稳定记忆
偏好用户长期喜欢/不喜欢是重要 Memory
事件发生过的重要事情是事件记忆
当前会话临时上下文是短期记忆，不一定长期保存

举例：

用户说：

text
“我不太喜欢被一直提醒体重，会更焦虑。”

原始聊天记录是：

text
用户说了这句话

Memory 应该提取成：

json
{
  "type": "preference",
  "content": "用户不喜欢频繁体重提醒，容易引发焦虑",
  "sensitivity": "medium",
  "usage_policy": "在提醒策略中降低体重相关主动触达频率"
}

4. Memory 的基本类型

A. Short-term Memory

短期记忆。

主要是：

text
当前会话上下文
最近几轮对话
当前任务临时状态

适合回答：

text
“你刚刚说的那个是什么意思？”
“继续刚才那个”
“那我该怎么做？”

B. Long-term Memory

长期记忆。

主要是：

text
长期偏好
稳定用户资料
重要事件
持续目标
关系上下文
未完成事项

C. User Profile Memory

用户画像记忆。

例如：

text
孕周 / 阶段
预产期
是否一胎
所在城市
就诊医院
家庭角色

这类更像结构化数据库信息。

D. Preference Memory

偏好记忆。

例如：

text
喜欢简短直接
不喜欢过度安慰
希望提醒少一点
希望解释更具体

E. Event Memory

事件记忆。

例如：

text
一次产检异常
一次重要担忧
一次医生建议
一次家庭沟通冲突
一次明确决定

F. Graph Memory

图谱记忆。

它不只是“记一句话”，核心是记关系。

例如：

text
用户 → 担心 → 某个检查指标
用户 → 不喜欢 → 频繁提醒
用户 → 正在处理 → 问医生清单
家人 → 影响 → 用户决策

Zep / Graphiti 这类方向强调用图结构表达长期记忆中的实体、关系和时间变化。无需一开始实现图谱记忆，但要知道它解决的是“关系和演化”的问题。

5. Memory 的读写链路

A. 读记忆

text
用户输入
→ 判断任务类型
→ 检索相关 Memory
→ 过滤不该注入的敏感记忆
→ 拼入 Context
→ 模型生成

B. 写记忆

text
用户输入 + 模型输出
→ 判断是否值得记
→ 判断记忆类型
→ 判断敏感级别
→ 写入 / 更新 / 忽略
→ 允许用户查看、编辑、删除

6. 什么值得记？

并非所有信息都值得写入记忆。

值得记的通常是：

text
1. 长期稳定资料
2. 明确偏好
3. 重复出现的关注点
4. 用户明确要求记住
5. 对未来任务有明显帮助的事件
6. 对安全和边界有帮助的信息

不应该乱记：

text
1. 一次性闲聊
2. 短期情绪波动
3. 敏感信息但没有明确用途
4. 会让用户有被监视感的信息
5. 用户没有授权的家庭隐私

7. Memory 的最大风险

Memory 的能力边界需要受控设计。

风险包括：

text
1. 记错
2. 过度记忆
3. 在不合适时机提起
4. 暴露敏感信息
5. 用户删除后仍被使用
6. 把短期状态误判成长期偏好
7. 让用户感觉被监控

所以 Memory 必须配套：

text
Memory Policy
User Control
Deletion
Suppression
Audit Log
Safety Rules

8. 学习者需要看懂的最小代码结构

python
# 伪代码：读取记忆
def build_context(user_id, user_message):
    memories = memory_store.search(
        user_id=user_id,
        query=user_message,
        top_k=5
    )
    safe_memories = filter_sensitive_memories(memories)
    context = {
        "user_message": user_message,
        "relevant_memories": safe_memories
    }
    return context

只需看懂：

text
memory_store.search() = 查相关记忆
filter_sensitive_memories() = 过滤不该用的记忆
context = 把记忆放进这次模型输入

9. Memory 和 RAG 的边界

问题更像 RAG更像 Memory
“糖耐异常是什么意思？”是否
“我之前是否说过我不想查太多资料？”否是
“孕晚期胎动减少有哪些注意事项？”是可能结合 Memory
“我现在是孕几周？”否，查用户资料是结构化状态
“上次医生怎么说的？”否，查记录/事件记忆是

一句话：

text
RAG 处理外部知识。
Memory 处理用户个人连续性。
