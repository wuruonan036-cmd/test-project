第 09 课 · Week 2

Context Engineering：模型本次可见信息的组织方法

学习 Context Pack 的组成、来源、选择、压缩、隔离与优先级策略。

Context上下文组装信息选择

课程目标

学习 Context Pack 的组成、来源、选择、压缩、隔离与优先级策略。

1. 课程目标

学完这一课，需要能回答：

text
1. 什么是 Context？
2. Context 和 Prompt 的区别是什么？
3. 为什么不能把所有历史都塞给模型？
4. Context Pack 是什么？
5. RAG、Memory、Tool Result、User State 怎么进入 Context？
6. Context Engineering 为什么是 AI 应用工程核心？

2. 定义

Context Engineering 是为模型这一次任务选择、组织、压缩和注入最有用信息的工程能力。

更直白地说：

Context Engineering 解决的是：模型这一次到底应该看见什么。

3. Context 并非 Prompt

很多人会把 Context 和 Prompt 混在一起。

概念本质例子
Prompt任务规则“请总结用户本次上传报告的重点”
Context任务材料用户上传的报告、孕周、历史检查记录、相关知识片段
Output Schema结果格式summary、risk_level、doctor_questions

一句话：

text
Prompt 规定怎么做。
Context 提供用什么信息做。

4. 为什么不能把所有历史都塞进去？

因为模型上下文窗口有限，而且信息越多不一定越好。

把所有信息都塞进去会导致：

text
1. 成本变高
2. 速度变慢
3. 重要信息被稀释
4. 旧信息干扰新任务
5. 隐私和安全风险增加
6. 模型更容易抓错重点

Context Engineering 的目标是筛选最小充分信息，而并非尽可能堆叠材料：

text
给模型最小充分信息。

5. Context Pack 是什么？

可以把 Context Pack 理解成：

text
这一次模型调用前，后端为模型打包的一份任务材料包。

一个 Context Pack 通常包括：

text
1. 当前用户输入
2. 当前页面入口
3. 当前用户状态
4. 最近对话摘要
5. 相关长期记忆
6. RAG 检索结果
7. 工具返回结果
8. 安全边界提示
9. 输出格式要求

注意：不同任务的 Context Pack 不一样。

6. Context Pack 示例

假设用户说：

text
“我上次那个指标是否还要问医生？”

模型如果只看到这句话，很难回答。

后端需要组装 Context Pack：

json
{
  "current_input": "我上次那个指标是否还要问医生？",
  "page_entry": "companion_chat",
  "user_state": {
    "stage": "pregnancy_second_trimester",
    "week": 22
  },
  "recent_summary": "用户上次上传过一份唐筛相关检查结果，并担心其中一个指标偏高。",
  "relevant_records": [
    "2026-05-10 检查记录：指标 A 略高，已建议下次产检询问医生。"
  ],
  "relevant_memory": [
    "用户倾向于先知道重点，再看详细解释。"
  ],
  "safety_notes": [
    "不要替代医生诊断。",
    "如果检查指标异常，应建议用户带报告咨询医生。"
  ]
}

这才是模型能稳定回答的基础。

7. Context 来源有哪些？

text
1. 当前输入：用户这次说的话、上传的图片、语音转写
2. 会话上下文：当前多轮对话里发生了什么
3. 用户状态：阶段、偏好、基础资料、权限
4. 业务数据：检查记录、提醒、任务、空间内容
5. RAG 结果：从知识库检索出来的片段
6. Memory：长期偏好、重要事件、用户画像
7. Tool Result：工具调用返回的数据
8. 安全规则：风险边界、不能说什么
9. 页面入口：从哪个页面触发这次请求

8. Context Engineering 在请求链路中的位置

text
用户输入
→ Harness 判断任务类型
→ 读取用户状态
→ 检索 Memory
→ 检索 RAG
→ 调用必要工具
→ 组装 Context Pack
→ 选择 Prompt
→ 调模型
→ 结构化输出
→ 安全检查
→ 返回结果

Context 是模型调用前的重要准备工作，而并非后补材料。

9. Context 和 Memory 的区别

概念本质示例
Memory长期可复用的用户状态用户偏好、长期担忧、历史事件
Context本次模型调用要看的信息包当前输入 + 相关记忆 + RAG + 工具结果

Memory 是仓库。 Context 是这次从仓库里拿出来的材料包。

10. Context 和 RAG 的区别

概念本质
RAG从外部知识库检索相关知识
Context把所有本次需要的信息组织进模型输入

RAG 是 Context 的一个来源。 Context 不等于 RAG。

text
Context = 当前输入 + 用户状态 + 历史摘要 + Memory + RAG + Tool Result + Safety Notes

11. Context 和 Tool Result 的关系

工具调用可能发生在模型前，也可能发生在模型中间。

例如：

text
用户问：“我下次产检是哪天？”
→ 后端调用数据库工具查询日程
→ 得到 Tool Result：“下次产检是 6 月 12 日”
→ 把结果放进 Context
→ 模型生成自然语言回复

Tool Result 也会成为 Context 的一部分。

12. 少量代码：只看结构

ts
const contextPack = {
  userInput,
  userProfile,
  recentConversationSummary,
  relevantMemories,
  retrievedKnowledge,
  safetyRules,
};
const response = await model.generate({
  prompt: selectedPrompt,
  context: contextPack,
});

只需看懂：

text
contextPack 是这次模型调用前准备好的材料包
selectedPrompt 是任务说明
model.generate 是模型调用

13. Context Engineering 的常见策略

13.1 选择 Select

只选择和本次任务相关的信息。

text
用户问检查结果 → 选检查记录、医学知识、风险边界
用户闲聊情绪 → 选最近对话、偏好记忆、陪伴风格
用户问历史事件 → 选相关空间记录和长期记忆

13.2 压缩 Compress

长对话不能全放，要压缩成摘要。

text
最近 20 轮对话 → 200 字摘要
三份检查记录 → 关键指标列表
用户长期偏好 → 3 条记忆

13.3 隔离 Isolate

不同类型信息不要混在一起。

text
用户输入
用户状态
历史摘要
记忆
知识库结果
安全规则
输出格式

分区清楚，模型更不容易混乱。

13.4 优先级排序 Prioritize

不同 Context 的重要性不同。

建议优先级：

text
1. 当前输入
2. 安全规则
3. 用户状态
4. 最近相关上下文
5. 业务数据
6. 长期记忆
7. RAG 知识片段
8. 低优先级历史信息

13.5 过期和冲突处理

Context 里经常会有旧信息。

例如：

text
旧记忆：用户孕 18 周
新资料：用户现在孕 24 周

系统必须知道：

text
新状态优先于旧记忆。
结构化资料优先于聊天推测。
用户显式修改优先于系统自动推断。

14. 实战判断：一个 Context Pack 好不好，看 5 点

text
1. 是否只包含本次任务需要的信息
2. 是否区分了用户输入、业务数据、记忆、知识和安全规则
3. 是否删除了过期或低相关信息
4. 是否把高风险规则放在足够高优先级
5. 是否能被日志记录和回放

阶段复盘

这三课连起来，要形成一个稳定理解：

text
Prompt Engineering：定义任务怎么做
Structured Output：定义结果怎么交付
Context Engineering：定义模型这次拿什么信息做

真实 AI 产品的模型调用，不应该是：

text
用户输入 → 一个大 Prompt → 模型回复

而应该是：

text
用户输入
→ Harness 判断任务
→ 选择 Prompt
→ 组装 Context Pack
→ 规定 Structured Output
→ 模型生成
→ 系统解析
→ 安全检查
→ 产品动作
→ 日志与评测

本阶段核心判断

text
1. Prompt 并非全部。
2. Context 往往比 Prompt 更影响结果。
3. Structured Output 是 AI 结果进入产品系统的桥。
4. Harness 的核心工作之一，就是管理 Prompt、Context 和 Output。
5. 这三者必须和日志、评测、安全、数据结构连接，否则只是 Demo。
