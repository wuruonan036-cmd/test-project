第 07 课 · Week 2

Prompt Engineering：模型任务协议设计

将 Prompt 作为产品级任务协议来设计，明确角色、输入、过程、输出、约束和降级策略。

Prompt任务协议模板

课程目标

将 Prompt 作为产品级任务协议来设计，明确角色、输入、过程、输出、约束和降级策略。

1. 课程目标

学完这一课，需要能回答：

text
1. Prompt 到底是什么？
2. Prompt 和普通文案有什么区别？
3. 为什么真实产品不能靠一个“万能 Prompt”？
4. 一个好 Prompt 应该包含哪些部分？
5. Prompt 在 Harness 里处于什么位置？
6. Prompt 和 Context、Structured Output 的边界是什么？

2. 定义

Prompt Engineering 是产品级任务协议设计。

更准确地说：

Prompt Engineering 是把一个模糊任务，转成模型可以执行、产品可以复用、工程可以评测的任务协议。

可以把 Prompt 理解成：

text
给模型看的任务说明书

它并非普通说明书，而应是产品系统的一部分。

3. 错误理解：将 Prompt 作为“聊天话术”

很多 0 基础的人会这样理解 Prompt：

text
你是一个专业助手，请温柔、准确地回答用户问题。

这只能算很初级的提示词。 在真实产品里，这种 Prompt 有几个问题：

text
1. 太泛，不能稳定完成具体任务
2. 没有输入边界
3. 没有输出格式
4. 没有失败处理
5. 没有安全边界
6. 没有和数据库、工具、记忆、评测连接

所以真实 AI 应用里，Prompt 更像一个 任务模板。

4. 一个产品级 Prompt 至少包含 8 个部分

text
1. 任务目标：这次到底要完成什么
2. 角色边界：模型应该以什么身份处理
3. 输入说明：系统会给模型哪些信息
4. 判断规则：模型应该怎么判断任务类型 / 风险 / 优先级
5. 输出要求：输出自然语言、JSON，还是二者都有
6. 禁止事项：不能做什么
7. 失败降级：信息不足时怎么办
8. 示例：给模型几个标准答案样式

5. 用一个简单例子理解

低质量 Prompt

text
请帮用户解释检查报告。

问题： 模型不知道解释到什么程度，也不知道是否要提醒风险，不知道是否要结构化输出，不知道是否要生成后续行动。

产品级 Prompt 雏形

text
你是一个健康信息解释助手。学习者的任务是把用户上传的检查结果解释成易懂语言。
你需要：
1. 先总结用户最需要知道的 1-3 个重点。
2. 区分“正常信息”“需要观察”“建议咨询医生”的内容。
3. 不要做诊断。
4. 不要给出药物或治疗方案。
5. 如果信息不足，请明确说明需要哪些信息。
6. 最后给出用户可以向医生确认的问题。
输出格式：
- summary：一句话总结
- key_points：重点列表
- risk_level：low / medium / high
- doctor_questions：建议问医生的问题

这个 Prompt 已经开始像工程模板了。

6. Prompt 在 AI 请求链路里的位置

一次 AI 请求大概是这样：

text
用户输入
→ 后端接收
→ Harness 判断任务
→ 选择 Prompt 模板
→ 组装 Context
→ 调用模型
→ 模型输出
→ 结构化解析
→ 安全检查
→ 返回前端 / 写入数据库

Prompt 不在最前面。 它通常是在 Harness 判断任务之后 被选择的。

也就是说：

text
不同用户输入应匹配不同 Prompt。

真实产品里应该是：

text
用户闲聊 → companion_chat_prompt
用户上传报告 → report_explain_prompt
用户想问医生 → doctor_question_prompt
用户表达风险信号 → safety_response_prompt
用户要求总结 → summary_prompt

7. Prompt 与 Context 的边界

这是必须分清的。

概念解决的问题示例
Prompt这次任务怎么做“请提取用户的 3 个核心问题，并按优先级排序”
Context这次任务拿什么信息做用户孕周、历史对话、上传报告、相关知识片段
Structured Output结果要长什么样JSON 字段、枚举、布尔值、列表

简单说：

text
Prompt = 规则
Context = 材料
Structured Output = 交付格式

8. Prompt 和 Harness 的关系

Harness 并非 Prompt。 Harness 是控制系统，Prompt 是它调用的一个模块。

text
Harness 负责：
1. 判断用户这次是什么任务
2. 决定用哪个 Prompt
3. 决定注入哪些 Context
4. 决定用哪个模型
5. 决定是否调用工具
6. 决定输出后是否要安全检查

Prompt 只负责：

text
在某个具体任务下，告诉模型如何处理。

9. 少量代码：只看结构

无需编写代码，只看工程位置。

ts
const prompt = `
你是一个健康信息解释助手。
任务：把用户上传的检查结果解释成易懂语言。
要求：
1. 不做诊断
2. 给出重点总结
3. 输出 JSON
`;
const response = await model.generate({
  prompt,
  input: userReportText,
});

只需看懂：

text
prompt = 任务说明
input = 用户材料
model.generate = 调模型
response = 模型结果

后面真实工程会更复杂，但本质就是这个。

10. 产品级 Prompt 模板

可以先记住这个模板：

text
# Role
明确模型角色，并设置边界。
# Task
明确本次任务。
# Input
明确输入信息。
# Process
明确处理步骤。
# Output
明确输出格式。
# Constraints
明确禁止行为。
# Fallback
信息不足、无法判断、风险过高时怎么办。
# Examples
给 1-3 个标准示例。

11. 实战判断：什么是“好 Prompt”？

高质量 Prompt 的标准主要包含 5 条：

text
1. 任务边界清楚
2. 输入材料清楚
3. 输出格式清楚
4. 禁止事项清楚
5. 能被评测和复用

差的 Prompt 通常是：

text
1. 只描述语气，不描述任务
2. 只描述理想效果，不描述输入输出
3. 只写“专业、温柔、准确”，没有判断规则
4. 所有场景共用一个大 Prompt
5. 一改就影响全系统
